# Serenity / @aleabitoreddit：Supply-Chain Bottleneck Lens

用途：把 Serenity 的公开帖子当作**发现供应链线索的研究输入**，再用原始披露验证。它不是跟单器、名人因子或收益证明。

## 身份与证据边界
用户提供的 X 主页对应 `@aleabitoreddit`，公开账号定位为 AI / Semiconductor Supply Chains Research。[S16]
其原帖能证明“他公开表达过什么”，但不能证明完整持仓、成交、成本、收益或未公开的亏损。
社区已有对其数千条帖子做结构化提炼的项目，可用作二手索引定位主题，但任何结论必须回到原帖和公司/交易所/客户原始材料验证。[S18]
不得把社区项目里未经独立复核的胜率、收益率、杠杆或人物背景写成事实。

## Bottleneck Alpha：七问
遇到 AI、半导体、光通信、存储、电力、数据中心基础设施等主题时，按顺序回答：

1. **最终需求**：真正增长的是训练、推理、存储、网络、电力还是别的负载？数量、周期和客户预算依据是什么？
2. **单位含量**：每一单位最终系统需要多少该部件/材料/设备？新架构让 content per system 上升还是下降？
3. **单点瓶颈**：限制交付的是材料、晶圆、设备、良率、封装、认证、IP、供电还是产能？瓶颈必须具体到可验证对象。
4. **替代难度**：供应商数量、认证周期、工艺迁移、设备交期、客户切换成本和扩产周期分别多久？
5. **半垄断性**：是否存在高集中度、少数可替代厂商或独有资质？“semi-monopoly”是研究假说，不是因作者使用该词就成立。[S17]
6. **利润捕获**：短缺能否转成 ASP、毛利、产能利用率、订单可见度、现金流或资本回报？若新增 CAPEX 很大，谁承担成本、谁赚到超额利润？
7. **预期差**：当前市值/估值已经隐含多少增长？真正的机会是“被低估的盈利弹性 × 兑现概率”，不是单纯“行业会增长”。

每一问必须输出：支持证据、反证/替代解释、未知、下一验证点。

## 供应链映射
从 hyperscaler/终端需求向上游逐级展开：
`最终客户 CAPEX/需求 → 系统架构 → 模块/子系统 → 关键芯片/材料/设备 → 上游原料/工艺`

对每一层记录：
- 供应商与客户关系：已命名量产 / 已命名订单 / qualification / design win / sample / 推测。
- 数量或价值含量：有来源才填；否则 null。
- 产能与扩产：现有能力、利用率、扩产时间、设备/良率约束。
- 替代路径：第二来源、技术替代、客户自研、降规格方案。
- 利润捕获：价格、毛利、现金流、资本开支和稀释。
- 时点：何时公开、何时可能兑现。

## Serenity 信号如何使用
### 高价值 discovery signal
- 新的上游依赖/单点故障；
- 公开资料里可验证的 qualification、订单、产能 allocation 或客户路径；
- 需求增长与供给扩张周期存在明显错配；
- 小市值供应商对巨大下游 CAPEX 有不对称利润弹性。

### 降权
- “这是下一个 X 倍股”等目标价/收益叙事；
- victory lap、涨后总结、截图收益；
- 没有持仓或明确 exploratory 的随手想法；
- 供应商列表但没有订单、认证、产能或利润链；
- 客户关系仅靠链式推测；
- 社区转述、聚合页面或第三方自动摘要。

Serenity 在 2026-03-17 原帖明确提到偏好 “semi-monopolies”，并将不同标的区分为 substrate-level favorites、steady compounders 与 highest-upside candidates。这只用于证明其公开研究偏好，不用于证明这些标的当前仍值得买。[S17]
他在 2026-03-19 将自己的叙事概括为 Photonics 与 Memory supercycles；这是作者自述的框架线索，不能据此证明完整投资绩效。[S19]

## Qualification Cycle 专项
对半导体/光子学小公司，不能把开发收入低、一次性费用或短期 GAAP 波动直接等同 thesis 失败；也不能把 qualification 自动当未来大单。
建立状态机：
`技术可行 → sample → 客户验证 → qualification → design win / allocation → production order → ramp → 收入确认 → 回款`
只有状态跃迁有原始证据时才升级 conviction。
同时记录失败路径：认证延迟、第二来源导入、客户取消、良率不达标、扩产稀释、价格下跌。

## Supercycle 判定
“超级周期”至少需要三组独立证据中的两组，并持续复核：
- 需求：客户 CAPEX、出货、订单、bit growth / bandwidth / power 等；
- 供给：产能、设备交期、库存、良率、原料或认证限制；
- 价格/利润：ASP、合同价、毛利、现金流或资本回报改善。

如果价格上涨但供给很快响应，或者需求增长被单位含量下降抵消，不称结构性 supercycle。
宏观/情绪导致短期跌幅不能自动否定长期 thesis；同样，长期 thesis 也不能覆盖仓位、流动性和估值风险。

## 与主 Skill 的合并方式
Serenity 负责 **idea discovery / bottleneck hypothesis**。
`references/research.md` 负责经济机制、财务质量、估值和利润验证。
`references/decisions.md` 负责期限、交易条件、仓位约束和四类退出。
`references/evidence.md` 负责证据等级、时点和隐私。

最终输出必须把：
**作者观点 → 原始事实 → 我们的推导 → 可证伪条件**
四栏分开。若公司/客户披露无法验证核心链条，状态最多到「继续研究/观察」，不能因为 Serenity 高 conviction 直接升级为条件计划。
